## Overview

BRAVE is a multimodal early-warning system for conveyor belt joint rupture and damage in iron ore mining plants. It fuses **computer vision** (a YOLO model trained to spot tears, holes, and belt joints on camera) with **sensor telemetry** (vibration, temperature, RPM, position, current) from an ESP32-based sensor rig, combining both into a single live risk score shown on a real-time dashboard.

The goal is early warning and risk estimation, not a guarantee — BRAVE does not claim 100% accuracy, guaranteed failure prevention, or the ability to see inside the belt's steel cords. It's a prototype demonstration of multimodal anomaly detection for predictive maintenance.

## How it works

```
 ESP32 Sensors                     USB Camera
      |                                 |
      v                                 v
 sensor_ai.py                    vision_gateway.py
 (Isolation Forest,               (YOLOv8, best_v3.pt)
  trained on normal                     |
  baseline data)                        v
      |                          vision_state.json
      |<----- reads vision score --------
      v
 dashboard_state.json
      |
      v
 Streamlit Dashboard (app.py)
 Control Room - Live Sensors - Belt Digital Twin
 Anomaly Detection - Fault Localization
 Predictive Maintenance - Alerts & Actions
```

Sensor readings are buffered into rolling windows, turned into statistical features (mean/std/slope), and scored for anomaly by an Isolation Forest trained only on the belt's normal operating behavior. That score is fused with the camera's live damage score (weighted: Vision 35% - Vibration 20% - Ultrasonic 18% - RPM 10% - Current 10% - Temperature 7%) into a single `risk_index` and `health_score`, which the dashboard displays and refreshes every 2 seconds.

## Hardware

| Component | Role |
|---|---|
| ESP32 | Central microcontroller, streams sensor JSON over USB serial |
| MPU6050 | Vibration sensing |
| DS18B20 | Temperature sensing |
| Hall sensor + magnets | RPM / belt position (4 pulses/revolution) |
| HC-SR04 | Ultrasonic belt-profile sensing (surface only — not for internal steel-cord damage) |
| INA219 *(optional)* | Current sensing |
| USB/UVC camera | Feeds the vision model |
| DC geared motor + driver | Drives the prototype belt rig |

Belt geometry (prototype rig): 40mm roller diameter, 1100mm belt loop, 6 zones, 6 tracked joints.

## Vision model

- Trained on the Roboflow "Conveyor Belt Damage" dataset (651 images, 5 classes: Belt Joint, Large Hole, Large Tear, Small Hole, Small Tear), CC BY 4.0.
- `best_v3.pt` is the current model — trained on a **video-level, leak-free split** (an earlier version had train/test leakage and is not used).
- Benchmarked on a true, never-touched holdout set: **F1 0.954, mAP50 0.985**. Large Tear remains the weakest class and the top candidate for more training data.

## Setup

```bash
pip install -r requirements.txt
pip install ultralytics opencv-python scikit-learn pyserial
```

In `data/live_data.py`, set:
```python
DEMO_MODE = False   # False = real hardware/camera. True = synthetic demo data.
```

In `config.py`, set `SERIAL_PORT` and `BAUD_RATE` to match your ESP32.

## Train the anomaly model (once, before live mode works)

With the belt running normally (no faults) and the ESP32 connected:

```bash
python sensor_ai.py --mode collect_baseline --source serial
python sensor_ai.py --mode train
```

This produces `isolation_forest.pkl`. Retrain if sensors, belt speed, or operating conditions change meaningfully.

## Running it live

Three processes, each in its own terminal:

```bash
python sensor_ai.py --mode live --source serial      # sensor fusion -> dashboard_state.json
python vision_gateway.py                               # camera + YOLO -> vision_state.json
streamlit run app.py                                    # the dashboard
```

Open the **Network URL** Streamlit prints to view the dashboard from another device on the same Wi-Fi.

> **Note:** `dashboard_gateway.py` is a retired placeholder gateway kept for reference. Do not run it alongside `sensor_ai.py` — both write `dashboard_state.json` and will overwrite each other.

## Known limitations

- No formal precision/recall benchmark yet for the sensor anomaly model (qualitative fault testing only).
- Vision model untested on hardware/camera/lighting setups outside the original training rig.
- Current camera feed refreshes as a still frame every ~2 seconds rather than continuous video, by design — a lower-risk trade-off for a demo than running a separate video-streaming server.
